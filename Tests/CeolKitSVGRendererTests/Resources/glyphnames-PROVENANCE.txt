Why it is checked in
--------------------
`SMuFLGlyphConformanceTests` asserts that every case of `SMuFLGlyph` names a real SMuFL glyph
and carries that glyph's real codepoint.  A wrong PUA codepoint does not crash and does not
fail to render — it silently engraves a different piece of notation — so the check is worth
having, and it has to run offline in CI.

This is a test resource only.  It is not part of any library product and is never shipped to
consumers of the package.

Relationship to SMuFL 1.4
-------------------------
The published file tracks the specification's working branch rather than the 1.4 release tag,
which carries no `metadata/` directory of its own.  As of this retrieval it is a strict
superset of 1.4: the eight `tuplet{Bracket,Parenthesis}*{Roman,Italic}` names added on
2026-08-06 are new, and no name has been removed and no codepoint reassigned.  That is the
general pattern — SMuFL appends to its ranges rather than reassigning within them — which is
what makes a pinned copy a safe oracle for the codepoints CeolKit already uses.

Updating
--------
Re-download from the URL above, update the retrieval date and SHA-256 here, and run the test
suite.  A conformance failure after such an update means the specification moved under a glyph
CeolKit draws, and wants investigating rather than papering over.
